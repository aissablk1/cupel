## Contexte

Les 4 projets concepts (Next.js 16.2.6) avaient reçu des headers de sécurité
basiques (HSTS, X-CTO, Referrer-Policy, X-Frame, Permissions-Policy) lors d'une
passe précédente. La directive `Content-Security-Policy` avait été
volontairement omise pour permettre une analyse à froid des domaines tiers
réellement utilisés par chaque app.

Cette session :

1. inventorie les domaines tiers détectés dans chaque code source,
2. compose une CSP fine par projet,
3. ajoute la directive `Content-Security-Policy` dans le bloc `headers()` du
   `next.config.*` (sans toucher aux autres headers),
4. valide via `next build`,
5. commit avec auteur `Aïssa BELKOUSSA <contact@aissabelkoussa.fr>`.

Snapshots des `next.config.*` originaux : `<projet>/_backup/csp_2026-05-20_19h00/`.

## CSP détaillées

### VALIBAN

Domaines tiers détectés : `fonts.googleapis.com` (CSS), `fonts.gstatic.com`
(WOFF), `api.valiban.com` (env), liens sortants `discord.gg` / `twitter.com` /
`github.com` (href uniquement, pas embarqués). Pas de Supabase, Sentry, PostHog,
Stripe, Vercel Analytics détectés.

```
default-src 'self';
script-src 'self' 'unsafe-inline' 'unsafe-eval';
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src 'self' https://fonts.gstatic.com;
img-src 'self' data: blob:;
connect-src 'self' https://api.valiban.com;
frame-src 'none';
frame-ancestors 'none';
base-uri 'self';
form-action 'self'
```

Fichier modifié : `apps/frontend/next.config.ts`
Commit : `22c5ef8c0263dba6eeec7abbd9549f1f9e95a33a`

### DropOrch

Domaines tiers détectés : `api.droporch.com` (env API), `transparenttextures.com`
(image CSS background-image dans `ContactView.tsx`). Fonts via `next/font/google`
(Inter + JetBrains Mono) — auto-hébergés par Next, pas de connexion runtime.
`gtag` référencé conditionnellement (`window.gtag` si présent) mais aucun script
GA n'est chargé dans `_document.tsx`, donc pas de domaine `googletagmanager.com`

```
connect-src 'self' https://api.droporch.com;
frame-src 'none';
frame-ancestors 'none';
base-uri 'self';
form-action 'self'
```

Fichier modifié : `apps/frontend/next.config.js`
Commit : `f48a179e228757e11fc0694f31ac9a6b4285a4c2`

### SELFPOD

Domaines tiers détectés : aucun en runtime. Inter via `next/font/google`
(auto-hébergé). API via `NEXT_PUBLIC_API_URL` (par défaut localhost, donc
même-origine en prod attendue). `output: 'export'` actif (Cloudflare Pages).

```
default-src 'self';
script-src 'self' 'unsafe-inline' 'unsafe-eval';
style-src 'self' 'unsafe-inline';
font-src 'self' data:;
img-src 'self' data: blob:;
connect-src 'self';
frame-src 'none';
frame-ancestors 'none';
base-uri 'self';
form-action 'self'
```

**Note `output: 'export'`** — La CSP est définie dans `next.config.js` mais
**ne sera PAS servie par Cloudflare Pages** en mode export statique pur
(`next build` log : `⚠ rewrites, redirects, and headers are not applied when
exporting your application`). Pour activation effective :

1. **Option 1 (CF Pages)** : dupliquer la CSP dans un fichier `public/_headers` :
   ```
   /*
     Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; ...
   ```
2. **Option 2 (SSR)** : retirer `output: 'export'` et déployer sur Vercel/Node
   runtime — la CSP du `next.config.js` s'activera automatiquement.

Le code est néanmoins conservé pour activation immédiate dès bascule.

Fichier modifié : `apps/frontend/next.config.js`
Commit : `698c4617e25aa0ab9a907e59b7580141f3e583a3`

## Durcissements possibles plus tard

- **Retirer `'unsafe-eval'` en prod** — nécessaire pour Next.js dev / Turbopack ;
  en prod build statique, plus rarement nécessaire. Conditionner via
  `process.env.NODE_ENV === 'production'` dans le `next.config`.
- **Retirer `'unsafe-inline'` du `script-src`** — passer à nonce-based ou
  hash-based, via middleware Next qui injecte le nonce dans `<Script>` tags
  (Next.js 13+ supporte `nonce` dans `next.config` headers via middleware).
- **Retirer `'unsafe-inline'` du `style-src`** — plus complexe car Tailwind +
  styled-jsx + Next inline styles. Acceptable de garder en l'état.
- **Trusted Types** — `require-trusted-types-for 'script'` pour bloquer les
  sinks XSS (innerHTML, eval, etc.). Compatibilité Chromium uniquement
  aujourd'hui.
- **Reporting** — ajouter `report-uri` ou `report-to` pointant vers un
  endpoint (Sentry, Report-URI.com, endpoint maison) pour collecter les
  violations en prod silent mode avant durcissement.
- **SELFPOD** — dupliquer la CSP dans `public/_headers` (Cloudflare Pages)
  pour activation effective sur le statique. À faire séparément.

## Points d'attention non corrigés (initiative scope)

- **DropOrch / `window.gtag`** — code prêt pour Google Analytics mais aucun
  script GA chargé. Le jour où GA est branché, ajouter `https://www.googletagmanager.com`
  dans `script-src` et `https://www.google-analytics.com` dans `connect-src`.
- **VALIBAN / `openapi.vercel.sh`** — mention dans le code (peut-être un lien
  de doc OpenAPI). Pas ajouté à la CSP car non chargé en runtime. À vérifier
  si lien embarqué dans une iframe : auquel cas ajouter à `frame-src`.
