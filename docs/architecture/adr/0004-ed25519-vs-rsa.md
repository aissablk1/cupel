# ADR 0004 — Signature des skills : Ed25519 vs RSA

- Statut : Accepté
- Date : 2026-05-14
- Auteur : Aïssa BELKOUSSA

## Contexte

Chaque version publiée d'un skill (archive ZIP : `SKILL.md` + ressources)
doit être signée par Cupel pour garantir :

1. **Intégrité** : l'archive téléchargée n'a pas été altérée
2. **Provenance** : la version vient bien de Cupel (pas d'un attaquant MITM)
3. **Vérifiabilité offline** : le CLI vérifie sans appel réseau via clé publique embarquée

Options cryptographiques :

1. **RSA-PSS 4096** (SHA-256)
2. **Ed25519** (EdDSA, courbe Curve25519)
3. **ECDSA P-256** (secp256r1)
4. **Sigstore / cosign** (X.509 + transparency log)

## Décision

**Ed25519** pour la signature des manifests skills, clé publique de Cupel
distribuée :

- Hardcodée dans `cupel` (rotation = release majeure CLI)
- Servie sur `https://cupel.dev/.well-known/cupel-pubkey` (HSTS + CAA)
- Mirror sur GitHub Releases `aissablk1/cupel`

Algorithme : `Ed25519` via `node:crypto.sign/verify` (Node 22 natif, sans
dépendance). Format de signature : raw 64 octets base64url.

## Conséquences

**Positives :**

- Signature ~64 octets vs 512 octets RSA-4096 = manifest plus léger
- Vérification ~10x plus rapide que RSA — important pour `cupel install`
- Pas de paramètres à se tromper (PSS salt length, MGF1, etc.)
- Standard moderne (RFC 8032), résistant aux side-channels par construction
- Implémenté nativement en Node 22, Deno, browsers via WebCrypto

**Négatives :**

- Moins répandu en entreprise legacy (irrelevant ici, cible = devs modernes)
- Pas de hardware HSM grand public Ed25519 jusqu'en ~2024 (résolu en 2026 :
  YubiKey 5 series + Cloudflare Keyless support Ed25519)

## Gestion des clés

- Clé privée stockée chiffrée (`age`) dans 1Password vault perso, copie
  off-line USB
- Rotation : tous les 12 mois OU immédiatement en cas de compromission
- Nouvelle clé annoncée 30 jours avant cutover dans `CHANGELOG.md`
- Période de transition : double signature (ancienne + nouvelle) pendant 30 j

## Alternatives rejetées

- **RSA-PSS** : taille, vitesse, complexité d'implémentation
- **ECDSA P-256** : risque de fuite nonce (Sony PS3 case), plus complexe à
  implémenter sans biais
- **Sigstore / cosign** : excellent mais dépendance forte à l'écosystème
  OIDC + Rekor, overkill phase 0 — réévaluer en phase 3 si Cupel ouvre
  aux signatures créateurs individuels
